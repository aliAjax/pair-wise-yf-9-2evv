# 桌游规则遗忘点卡片库

一个纯前端本地应用，用来管理桌游收藏中的规则遗忘点、常见争议、开局准备和计分提醒。支持按最近未玩、人数范围和复杂度筛选，并在详情里展示聚会前快速复习卡片。

直接打开 `index.html` 即可使用，也可以在本目录启动静态服务访问。所有数据存在浏览器 localStorage，不依赖后端。

## 本地账机制

数据层在 `ledger.js`（与界面解耦，可在 Node 中直接引用测试），界面层在 `app.js`。

- **每条规则带自己的编号**：规则不再是纯字符串，而是 `{ id, text, updatedAt }` 条目，增删改都按编号对上。
- **多页面逐条合并**：主持和场务在两个标签页同时改同一张卡片时，通过 `storage` 事件做 base/local/incoming 三路合并，逐条而不是整卡覆盖。两边各自新增的条目都会保留。
- **冲突留两份并标出**：同一条规则两边都改过（或一边删除、另一边修改），合并后在卡片上列出所有版本并标红「冲突」，由人选择「保留这份」或「确认删除」；两个页面最终收敛到完全一致的状态。
- **删除墓碑防复活**：移除条目时写入墓碑（tombstone）。其他页面再保存时，这条不会因为它那边还留着又冒出来。整张桌游删除时其墓碑一并清掉。
- **容量不足先保规则文字**：配额不够时，按「最久未玩」顺序先把旧封面降级成占位（界面标「封面已降级」）；如果主账+备份仍放不下，再依次放弃备份里更老的封面。任何情况下规则文字和条目编号都不动，最后才清理超过 60 天的墓碑。
- **上一次完整内容备份**：每次保存同时写主账和一份完整备份（`...:backup`），备份里保留被降级的封面、规则始终最新。主账写坏（半截 JSON、损坏）时自动用备份恢复；保存失败时改动留在本页内存，可「重试保存」或手动「用上次完整内容恢复」。
- **旧数据自动升级**：v1 旧数据（规则是字符串、没有编号）首次打开时升级为 v2，为每条规则补齐编号。同一游戏、同一栏目、同一位置、同一文本在任何页面算出相同编号，避免两个页面各自升级后产生重复。
